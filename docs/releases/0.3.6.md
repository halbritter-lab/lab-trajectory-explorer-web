# v0.3.6 — Data preparation in cohort models, compact table cells

Cohort models have a *Data preparation* select with the presets offered under
Trajectories. It changes the same settings Trajectories uses: the parameter's
own settings when it has some, otherwise the shared ones, and a note under the
select says which. A parameter set to "No fit", for example by the acute review
preset, can now be made fittable without leaving the page. Choosing a preset
keeps the model parameter shown, and changing the settings on either page
discards the models fitted for that parameter, as before.

The Trajectories table has a *Cell details* option. *Compact* shows per cell
the measurement count with fitted count and span, the slope and the quality
label, and moves rolling windows, slope CI, quality explanation, endpoint
details and exclusions into one *Details* disclosure. *Full details* is the
default and unchanged.

Unapplied projection settings are previewed below the projection controls with
the remaining years per enabled target. The preview is computed by the same
function as the applied table; the table and the export keep the applied
settings until *Apply*.

Numerical calculations, data formats and exported values are unchanged. The
header displays v0.3.6.

The owner asked on 2026-10-14 for a review of these changes and their release.
Research/user acceptance remains open as documented for v0.3.0; this release
does not claim clinical acceptance.

Local verification: 915 unit/component tests, the production build and all 46
Chromium checks passed. In the browser with the demo data, choosing CKD
progression under Cohort models changed the shared settings, and the
Trajectories table then showed 12 fitted of 14 measurements per cell in the
compact view. An independent review found ten issues, among them that the
preselected model parameter could move after a preparation change, that the
select did not say it changes shared settings, stale guidance pointing only to
Trajectories, the method reference not yet describing the new control, and a
duplicated projection computation. All were fixed before release. Actual
release-triggered deployment evidence will be added to the GitHub Release after
publication.
