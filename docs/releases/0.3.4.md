# v0.3.4 — Cohort models from the demo, workspace UX review

Cohort models no longer open on a parameter that cannot be fitted. The page
preselects the first parameter, eGFR first, whose whole-cohort rows pass the
model's preparation and validation with the standard model, and follows newly
computed eGFR until a parameter is chosen by hand. The demo workbook now
carries imported eGFR for 11 of 14 patients (CKD-EPI 2021 values computed from
same-day creatinine for six patients), so loading the demo and fitting a cohort
model works with the default settings. Before, the preselected imported eGFR
had five patients, below the ten-patient minimum, and only Kreatinin [mg/dl]
could be fitted.

An impeccable UX critique of the workspace (24/40) led to these changes:
Cohort models uses the workspace colours and type instead of a separate dark
palette with emoji presets, holds a single Fit model action ("Refit model"
after a current fit) and rounds table values like the chart legend. Trajectories
has a "Show trends and slopes" switch next to the view choice. Muted text,
eyebrows, table headers, the dataset bar and the research-use footer meet WCAG
AA contrast. Counts use the singular where it applies, table cells name
exclusion reasons in words, imports with rejected rows use the warning style,
and empty cells no longer show a "G5 n < 3" badge.

Numerical calculations, data formats and exported values are unchanged; the
golden fixtures use their own workbook copies and did not move. The header
displays v0.3.4.

The owner asked on 2026-10-12 to merge and deploy this scope after reviewing the
cohort model behaviour with the demo data. Research/user acceptance remains open
as documented for v0.3.0; this release does not claim clinical acceptance.

Local verification: 908 unit/component tests, the production build and all 46
Chromium checks passed; a real WebR fit on the demo returned −2.79
ml/min/1,73m²/yr for eGFR and 0.12 mg/dl/yr for Kreatinin [mg/dl]. An
independent branch review found two important and four minor issues, all fixed
before release. Actual release-triggered deployment evidence will be added to
the GitHub Release after publication.
